# Security policy

## Reporting a vulnerability

Use GitHub private vulnerability reporting when it is enabled for the affected repository.

When private reporting is unavailable, email `info@nexarion.tech` with the subject line `Private security report - <repository name>`.

Include only the minimum information needed to reproduce the issue:

- affected repository and version or commit;
- a concise impact statement;
- reproducible steps using synthetic or non-sensitive data;
- relevant logs with secrets and personal data removed;
- a safe method for follow-up contact.

Do not open a public issue for an unpatched vulnerability. Do not include credentials, access tokens, private infrastructure details, client information, or production data in a report.

## Scope

Public Nexarion repositories are sanitized demonstrations. Their security policies cover the code and configuration explicitly published in those repositories. Private systems, client environments, internal GitLab repositories, and unpublished Keystone materials are outside the public repository scope.

## Safe-harbor intent

Good-faith research that avoids privacy violations, service disruption, data destruction, social engineering, credential theft, and access beyond what is necessary to demonstrate a vulnerability will be reviewed responsibly.
