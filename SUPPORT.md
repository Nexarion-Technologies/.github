# Support

## Public repositories

Use the repository issue tracker for reproducible bugs, documentation corrections, portability problems, and bounded feature proposals related to the published demonstration.

Before opening an issue:

1. confirm the problem occurs against the current default branch or latest release;
2. remove credentials, personal data, client information, and private infrastructure details;
3. reproduce the issue using synthetic or non-sensitive data;
4. include the operating system, runtime version, command, expected result, and observed result;
5. review the repository README, open issues, and security policy.

## Security reports

Do not use a public issue for an unpatched vulnerability. Follow `SECURITY.md` and use private vulnerability reporting where available.

## Commercial and private-environment support

Public issue trackers are not a support channel for client environments, production systems, contracts, billing, or confidential implementation work. Use the established private support channel or contact `info@nexarion.tech` for a properly scoped engagement.
